Read `design/10-design.md`, `design/20-contract.md`, and `design/00-brief.md`. Write `docs/docs/guide.md`.

If the repository has no `docs/` documentation project, write `guide.md` at the repository root instead and say that you did. Do not create a `docs/docs/` tree that nothing serves.

**Write for an experienced developer who has to use this system — not for the architect who designed it.** That single distinction decides everything you cut. They need to know what it does, how to work with it, and what will bite them. They do not need to know why it beat the alternatives.

The file opens with:

```
> Generated from `design/` by `/make-human-docs`. Do not edit by hand — edit the
> design docs and regenerate. `/reconcile` reports when this has gone stale.
```

## Rules

- **Never change technical meaning.** If the design admits two readings, that is a finding: report it and stop. Do not resolve an ambiguity by picking the one that reads better.
- **Cut internal reasoning.** Decision rationale, rejected alternatives, open questions and the argument for a boundary all belong to `design/`. Keep a rejected alternative **only** where the reader will otherwise ask "why not X?" *and* the answer changes how they use the thing. That is the bar — not whether it is interesting.
- **Replace cross-references with the thing itself.** "See §4.2" is useless to someone reading top to bottom. Say the sentence.
- **Merge and reorder for sequential reading.** The design docs are organised so they can be checked for correctness; this is organised so it can be read once, in order. Merge sections that are separate only because they were written separately.
- **Link back rather than duplicate detail.** Exact signatures, schemas and error tables stay in `design/20-contract.md` and are linked, never copied. A copied signature is the second copy that drifts.
- **Diagrams in Mermaid**, in fenced ```mermaid blocks — they render both on the code host and in Docusaurus. One per major flow or boundary. Not one per section.
- **Emit `sidebar_position` front matter.** Where the sidebar is autogenerated the page appears on its own; **where `sidebar.ts` is manual, a new page is invisible until it is listed there** — say so in your report rather than assuming it will show up.

## Stop conditions

- `10-design.md` or `20-contract.md` is empty or too thin to describe a working system. Say what is missing; do not fill the gap with plausible prose.
- The design and the contract disagree. That is `/reconcile`'s job, not this one.
- You would have to invent behaviour to make the guide read coherently.

Report what you cut, and anything the design left ambiguous.
