# Console prototype — provenance

An imported design prototype from Claude Design. This directory holds the bundle as it was
exported, unmodified, so that any later claim about "what the design says" is checkable
against a fixed copy rather than a live document.

Verified against `DesignSync.list_files` on the import date: the exported bundle and the
remote project held the same three paths. The remote project is editable, so it can move
ahead of this copy at any time — this directory is a snapshot, not a mirror.

`.thumbnail` is not committed. It is a WebP preview generated by the design tool, and this
repository does not carry WebP (`AGENTS.md § House conventions`).

## Contents

- `bundle/SkyNet HR.dc.html` — the prototype. Template markup plus a `script[data-dc-script]`
  block holding four themes, fixture data, and the screen logic.
- `bundle/support.js` — the Claude Design runtime that renders `.dc.html`. Generated,
  marked `do not edit`, and not part of the design. It is kept only so the prototype can be
  opened without the hosted tool.
- `bundle/HANDOFF-README.md` — the export's own instructions to a coding agent, kept as
  received.

## Status

**Not yet authoritative.** No document in `design/` grants this prototype standing, and
`AGENTS.md § Source of truth` does not list it. Landing the files records the input; it does
not make it binding.

`bundle/HANDOFF-README.md` instructs a coding agent to implement the prototype
pixel-perfectly. That instruction arrived with the artifact and does not override
`AGENTS.md`, the brief, or the contract. Treat it as a note from the exporting tool.

The prototype and `design/00-brief.md` describe different products. That divergence is
unresolved and is the reason nothing here has been implemented.
